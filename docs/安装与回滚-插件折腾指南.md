# DSH 插件 · 安装与回滚指南

> 写给想自己折腾 DSH 插件的人。
> **先说最要紧的一句:改坏了不用重装系统,删掉一个文件夹就能让 DSH 重新打开。**
> 核实时间:2026-09-29 · 实测环境:Windows ＋ DSH `0.1.5-rc.3`

---

## 一、为什么"改坏就打不开"

DSH 启动时会**加载一个 profile 里列出的所有插件**。只要其中一个插件在加载时抛错,宿主就可能起不来 —— 表现就是**界面打不开、窗口一闪而过、或者卡在启动画面**。

所以规矩只有一条:

> **动插件之前,先备份;动完之后,先别关掉现在能用的那一份。**

---

## 二、插件的真实结构(Windows 实测)

| 东西 | 在哪儿 | 说明 |
|---|---|---|
| **DSH 本体** | `%APPDATA%\npm\node_modules\@deepseek-ai\dsh` | 用 `npm i -g @deepseek-ai/dsh` 装的 |
| **profile 配置** | `~\.dsh\profiles\<名字>\package.json` | 插件清单写在这(名字通常是 `web`) |
| **patch 层** | `~\.dsh\profiles\<名字>\cordis.patch.yml` | 对插件行为的局部覆盖,也属于"会被改坏"的东西 |
| **装好的插件** | `~\.dsh\profiles\<名字>\node_modules\` | ⚠️ **这是安装产物,不要在这里改任何文件** |
| **插件源码** | 看 `package.json` 里写的是 `link:...` 还是版本号 | `link:` 的那几个才是"改了就能生效"的 |
| **自研插件的源码** | `D:\dsh\大肥鱼\插件源码\` | 本机实测的路径,别人机器上要看 `link:` 指向 |

**关键机制(实测):** profile 的 `node_modules` 里,自研插件是 **Junction(目录联接)**,直接指向源码目录:

```
~\.dsh\profiles\web\node_modules\dsh-auto-handoff
    -> D:\dsh\大肥鱼\插件源码\dsh-auto-handoff
```

不放心的话自己验一条命令(Windows PowerShell):

```powershell
Get-Item "$env:USERPROFILE\.dsh\profiles\web\node_modules\dsh-auto-handoff" -Force |
  Select-Object LinkType, Target
```

看到 `LinkType=Junction`、`Target=` 指向你的源码目录 —— 就说明**改源码 = 改生效的那份,不用重新安装**。

## 三、怎么装一个插件

```powershell
# 用官方命令装(推荐)
dsh plugin --profile web add dsh-selfwake

# 装自己写的、或者要从源码改的 —— 用 link,不要复制
# 在 profile 的 package.json 的 dependencies 里写:
#   "dsh-selfwake": "link:D:/你的路径/dsh-selfwake"
# 然后:
cd "$env:USERPROFILE\.dsh\profiles\web"
npm install          # 或 pnpm install
```

**装完必须重启 DSH 才生效**(插件是启动时加载的)。

## 四、改之前必做:备份

**最小备份(10 秒,针对你要改的那一个插件):**

```powershell
Copy-Item "D:\你的路径\dsh-selfwake" `
          "D:\你的路径\dsh-selfwake.bak-20260929" -Recurse
```

**完整备份(想更稳,把整个配置目录打一份):**

```powershell
$ts = Get-Date -Format "yyyyMMdd-HHmmss"
$src = "$env:USERPROFILE\.dsh\profiles\web"
$dst = "$env:USERPROFILE\dsh-profile-backup-$ts.zip"

# 只打配置和源码,不打 node_modules(它又大又能重装)
Compress-Archive -Path "$src\package.json","$src\cordis.yml","$src\cordis.patch.yml" `
                 -DestinationPath $dst
```

> **为什么可以不打 `node_modules`:** 装出来的东西跑 `npm install` 就能重建,真正不可再生的只有 **`package.json` / `cordis.yml` / `cordis.patch.yml` 这三个文件** + **你自己的插件源码**。

## 五、改坏了怎么救:三层恢复

### 第 1 层 —— 最快(针对性,让 DSH 一定能开)

症状:改完某个插件后 DSH 打不开。

```powershell
# ① 把出问题的那个插件从 profile 里摘掉(删掉的就是个 Junction,不碰源码)
Remove-Item "$env:USERPROFILE\.dsh\profiles\web\node_modules\<插件名>" -Recurse -Force

# ② 同时从 package.json 里删掉那一行依赖(用记事本改,或在 dependencies 里删这一项)

# ③ 重启 DSH
```

插件没了,DSH 只是**少一个功能**,但**能开**。这就是为什么"删文件夹"是救命绳。

### 第 2 层 —— 恢复源码

```powershell
Remove-Item "D:\你的路径\dsh-selfwake" -Recurse -Force
Rename-Item "D:\你的路径\dsh-selfwake.bak-20260929" "dsh-selfwake"
```

因为链接是 Junction,**源码目录改回来 = 生效的版本就回去了**,不用重装。

### 第 3 层 —— 整份配置回滚(上面都不行时)

```powershell
$src = "$env:USERPROFILE\.dsh\profiles\web"
Remove-Item $src -Recurse -Force
# 用你备份的那份 zip 解回去,再 npm install
```

## 七、出问题来反馈,请带四样

光说"装不上"没法修。给这四样,基本一次就能定位:

1. **DSH 版本** — `npm ls -g @deepseek-ai/dsh`
2. **插件名和版本** — 在 profile 的 `package.json` 里,或插件的 `package.json`
3. **报错原文**(截图也行,但原文更好)— 通常是 DSH 启动窗口或日志里的那几行
4. **你做了什么** — "我改了哪个文件、改了什么、然后重启就变成这样"

## 九、两个容易踩的坑

1. **改错地方** —— 有人会去 `node_modules` 里直接改,那改的是安装产物:重装一次就没了,而且可能和源码分叉。**只改源码目录。**
2. **改了没重启** —— DSH 的插件是**启动时加载**的,改完源码不重启,运行中的还是内存里的旧代码。**看到"还在用旧行为"先想这一步。**

## 附:三个插件的仓库

- `dsh-memory-board` — 把本地记忆档案(日记/状态/生长记录)搬进设置页面板
- `dsh-selfwake` — 到点主动开口(四道闸:间隔/安静/未回话上限/静默时段)
- `dsh-session-switch` — 交接:建新会话、把交接包送进去、写 pending 供界面切换

均公开在 GitHub `S3K926`,MIT 许可。
